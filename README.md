# 共视 · Co-Watch Player

> 不是你一个人在看。

这是一个“播放器本身也是观看者”的实验性播放器原型。

普通播放器遵循：`用户 → 播放器 → 视频`。

共视尝试：`用户 ↔ 播放器 ↔ 视频`。

播放器不是透明工具。它可以拥有注意力、习惯、记忆和轻微的控制欲。

## 目前原型已经做了什么

- 本地选择多个视频并形成片单
- 自定义播放 / 暂停 / 拖动 / 全屏控制
- 根据音频强度让时间轴出现呼吸、躁动、注意力变化
- “时间争夺”：播放器会偶尔回看、前跳，或在你拖动后把时间推/拉一点
- “暂停争夺”：播放器偶尔会拒绝立即停下来，坚持再看一点
- “节奏干预”：播放器可短暂改变播放速度
- “串台”：允许后，播放器可突然跳到片单另一视频的随机片段，几秒后回到原视频原位置
- “关系记忆”：仅使用浏览器 localStorage 记录共同观看时长、用户拖动、暂停和播放器越界次数
- 自主性滑块：从 0% 的普通播放器逐渐变成越来越有自己意见的观看者
- “现在，做点什么”按钮：方便立刻测试一次自主行为

## 运行

这是零依赖原型。

直接双击 `index.html` 即可使用现代浏览器打开。

推荐 Chrome / Edge。

如果浏览器对本地文件策略有限制，可在该目录执行：

```bash
python -m http.server 5173
```

然后访问 `http://localhost:5173`。

## 这不是最终技术架构

当前版本故意使用原生 HTML/CSS/JS，只用于最快验证“共视感”是否成立。

真正桌面版本建议：

- UI：Tauri + React / Solid
- 播放内核：libmpv
- 媒体解析：FFmpeg / libavformat
- 本地记忆：SQLite
- 内容感知：先做音频能量、场景切换、字幕密度、画面运动，不急着上大模型
- 后续 AI：只作为“理解与联想层”，而不是整个产品的唯一卖点

## 一条重要原则

不要把“怪”理解成随机 Bug。

每一次越界行为最好都满足：

1. 能被用户感知为“它做的”
2. 频率足够克制，不至于一分钟烦五次
3. 最好能与正在播放的视频或长期观看记忆建立因果关系
4. 可以逐渐形成性格，而不是固定特效

## 下一阶段

第一阶段目标不是完善播放器，而是验证一句话：

> 当用户看了 20 分钟以后，他会不会下意识觉得旁边真的还有“谁”在一起看？
