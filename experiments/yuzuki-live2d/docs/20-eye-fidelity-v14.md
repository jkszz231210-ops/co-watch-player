# V1.4 眼部质量修复说明（2026-10-09）

## 修复缘由

实际 V1.1 演示反馈：左右眼大小不协调、眼球/睫毛边界有机械剪切感，动画导致角色产生伪人感。旧方案先从原画中抹除眼睛，再从不同裁剪图中拼接虹膜、眼白和眼线。这种方式在没有画师重绘隐藏结构的情况下容易产生明显违和。

## 本版实际交付

1. **默认睁眼状态原画保真**：完整加载审核过的 `web/assets/yuzuki-front-a.webp`，不再将抠出的眼睛贴到脸上；浏览器端比较每个眼部像素，与审核原画完全一致。
2. **专用眨眼画片**：离线脚本 `tools/paint_blink_v14.py` 将左右眼分别绘制为 9 档透明眼睑覆盖，共 18 张过渡源图，网页加载 `blink-atlas.webp` 纹理图集。
3. **保持角色天然视角差异**：左右眼有不同的画面坐标与眼线曲线，取消用一个眼部轮廓镜像另一边的策略；常规眨眼共享同一闭合时间轴，单眼 Wink 保留独立控制。
4. **保守演出**：关闭此前会牵扯原画睫毛轮廓的虹膜平移和自动眉毛叠画。当前鼠标视线指令保留接口，但不会强行推动画片；要恢复真正视线移动须先完成独立眼球/眼白/上睑遮挡的专业美术。
5. **免安装版本、悬浮挂件、网页嵌入版本**均采用同一套 V1.4 渲染器。打包器以单张图集代替 18 次加载，失败时保留原画兜底。

## 尚存问题 / 不可夸大

- 半闭眼过程中，局部虹膜、眼线有些残影或绘画感不足；这是程序生成眼睑的局限，仍须画师手绘 0/0.25/0.5/0.75/1 五大关键形以及细化睫毛与阴影。
- 没有 Cubism `.cmo3/.moc3`；没有完整的头部 XY 变形、独立发丝物理、音素级口型。不能把现有 Web 2D 原型当作专业 Live2D 成品。
- 原画自然的不对称不是“反向强制镜像”即可消除的问题。画师绑定时需以五官相对比例协调为准。
