# 06 · 项目路线与真实工作量

## 阶段 A：目前交付（已完成）

- 两张角色概念图及 16 张情绪参考裁图。
- 可运行的网页角色展示/交互实验室。
- 情绪参数状态机原型、模拟对话、浏览器 TTS、基础单元测试。
- 可交给画师、绑定师和前端工程师继续工作的说明与验收标准。

## 阶段 B：美术定稿（未完成，最高优先级）

- 对当前装饰密度做减法，避免过于游戏商插化；明确右侧花饰、黑茶长发、灰蓝眼的统一标准。
- 绘制符合 Live2D 绑定的中立正面脸 + 独立五官标准图。
- 分层、补画、人工检查 PSD，至少完成眼白/瞳孔/虹膜/上下眼皮、口腔、发际、侧发、脸底。

## 阶段 C：Live2D 绑定（未完成）

- 导入 PSD，新建脸/眼/口/身体网格及变形器。
- 完成头部 XY/Z、双眼、眉毛、嘴型、身体倾斜、物理。
- 制作表情 `*.exp3.json`、动作 `*.motion3.json`，导出真实 `*.model3.json`。

## 阶段 D：真实角色驱动（未完成）

- 集成官方 Cubism Web SDK 渲染模块与完整模型文件。
- 将 `CharacterEngine` 中的统一情绪标签映射成 Cubism 参数曲线，实现嘴形和语音共存。
- 接入后端对话代理、音频包络/音素时间线、可选麦克风采集。

## 阶段 E：多端复用（未完成）

- 提取独立的角色组件/SDK 适配层，供网站引用。
- 桌面端封装、性能降级和自动更新。
- 之后再考虑游戏内渲染、移动端和更多服装模型。

## 最大风险

1. **美术一致性**：生成式素材对多视角、分层和表情中人物同一性控制仍不稳定。
2. **分层真实有效性**：单一 PNG 自动拆层常有遮挡缺口，专业修图/重画难以省略。
3. **变形质量**：自动网格、模板迁移可以提速，但不保证复杂眉眼口与头部转向质量。
4. **SDK/资源许可**：正式发布前核对所用模型、SDK、图片、音频的授权边界。
5. **交互表现**：情绪判定过强可能令人不适，应对节奏与强度限制进行体验测试。

## 定义 MVP

MVP 不等于只有一张能漂浮的图片。达到以下条件才可以对外称为“Live2D AI 角色”：具有真实 Cubism 可运行模型（`.model3.json` 和完整资源）；脸部至少实现左右眨眼、眉毛、微笑/开口/惊讶；可运行语音与表情互动；能部署到网页；通过最少一轮真人主观美术验收。
