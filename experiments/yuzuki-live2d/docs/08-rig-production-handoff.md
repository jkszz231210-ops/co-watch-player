# 08 · 从审核稿到专业 Live2D 的生产交接单

状态：**待美术方向审核后启动正式分层生产；以下是交付标准，不代表资产已经完成。**

## 画师交付底稿

- 中立正面视角：头部居中、正对摄像机、无歪头、双眼自然睁开、嘴巴自然闭合。
- 目标画布：3072×4608（RGBA；如采用更大尺寸需按性能重新评估），所有透明零件使用统一坐标系。
- 帧外绘制：不要让头发、袖子等关键需要摆动的部件被画布过早裁断。
- 脸部区域无文字、无多重滤镜干扰、无死贴在皮肤上的高光。
- 装饰可保留主题花饰和蓝色蝴蝶结，但不为增加复杂度而增加无必要的小挂件。

## 建议分层数量与清单

- **脸底**：头部肤色、脸颊阴影、两侧耳朵、脖子、下巴；侧脸和刘海遮挡处需补画。
- **每只眼睛**：眼白、虹膜、瞳孔、两层高光、上眼线及睫毛、下眼线、上下眼皮、闭眼辅助形、上/下可选阴影（建议不少于 10 组素材/眼）。
- **两只眉毛**：独立眉毛和辅助阴影，支持左右差异化抬眉。
- **嘴巴**：闭嘴轮廓、口腔底色、上唇/下唇线、牙齿、舌头；至少支持闭嘴、微笑、张嘴和 O 型口，口腔内部必须独立。
- **头发**：顶部主发、前刘海、左/右前侧发、鬓发、左/右后发、若干发尾，重点分离头发下原本看不见的额头和耳朵。
- **身体**：颈部、左/右肩、衣身、胸前蝴蝶结、花饰与项链、衣袖、衣摆；要运动的结构按物理分组。
- **附加**：腮红、泪光、汗滴等透明效果不应和脸底合并。

## 质量门禁

| 检查点 | 一票否决条件 |
|---|---|
| 正面五官 | 两眼不对齐、嘴巴在中心偏移过大、脸部被发束严重挡住 |
| 图层完整性 | 前发拖开后出现空洞、嘴部张开可见原底图、虹膜无法独立移动 |
| 透明度 | 本应透明的素材带白色/灰色背景边 |
| 文件坐标 | 图层分别裁剪却丢失对应画布坐标，导入后错位 |
| 表情空间 | 只有预合成笑脸、没有可独立调整的眉/眼/嘴 |
| 设计一致性 | 不同表情换了脸、瞳色不统一、头饰位置忽左忽右 |

## Cubism 分组与标准参数

必做：`ParamAngleX/Y/Z`、`ParamEyeLOpen/ROpen`、`ParamEyeBallX/Y`、`ParamBrowLY/RY`、`ParamMouthOpenY`、`ParamMouthForm`、`ParamBodyAngleX/Z`、`ParamBreath`。增配：眼笑、腮红、泪光、瞳孔微动等。注意模型中存在参数才能驱动，控制器的参数不是模型自动生成的依据。

Cubism 官方导入 PSD 会将图层转换为 ArtMesh；为可靠导入，最终 PSD 应把**同一零件的线稿与填色合并到一层**，但不同动作的零件彼此保持分离。依据官方说明：[PSD 导入](https://docs.live2d.com/en/cubism-editor-manual/psd-import/)、[立绘处理](https://docs.live2d.com/en/cubism-editor-tutorials/psd/)。

## 绑定演出验收动作

1. 左右转头 ±20°，上下转头 ±12°，不得露出空洞或五官串位；超过范围需另行精修。
2. 双眼独立闭合、笑眼、疑惑单侧抬眉。
3. 自然微笑、说话张口、惊讶 O 嘴之间平滑过渡，口腔内部无穿插。
4. 腮红与目光避让可与说话叠加，避免面部标签简单切图。
5. 简单身体呼吸、发丝惯性物理，减小静止悬浮感。
6. 导出 `.model3.json` + `.moc3` + 贴图与表情动作文件；Web SDK 逐项验证。

## SDK 的许可边界

Cubism Web SDK 需要通过官方渠道获取，Core 为专有组件，不随此仓库擅自分发。正式发布应核对用途对应的许可和衍生应用规则；参考 https://www.live2d.com/en/sdk/license/ 。
